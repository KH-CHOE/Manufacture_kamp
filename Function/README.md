# 다음 15분 전력 예측 — 단일 파이프라인

원자료 한 장에서 시작해 **모든 모델이 똑같이 전처리된 자료 하나**를 쓰게 만든 판이다.
전처리와 모델링이 파일 두 개로 갈려 있고, 그 사이를 CSV 한 장이 잇는다.

```
Dataset/raw/*.csv ──preprocessing.py──▶ Dataset/preprocessed/processed.csv
                                              (+ manifest)
                                                     │
                                          modeling.py ──▶ results.json (+ joblib/pt)
```

자료는 저장소의 `Dataset/` 에, 학습 산출물은 `Model/` 에 모여 있다. 세 벌로 갈라지지 않게 한 곳만 쓴다.
`--raw`·`--out` 으로 언제든 다른 경로를 줄 수 있다 — **2022년 자료는 그렇게 넣는다.**

## 왜 이렇게 만들었나

앞선 판들은 모델마다 전처리가 조금씩 달랐다. 그래서 수치를 나란히 놓을 수 없었다 —
시험 행수가 4,991 / 7,104 / 7,294 / 23,425 / 23,904 로 갈렸고, 같은 모델도 기준이
바뀌면 값이 달라졌다. 이 판은 그 문제를 구조로 막는다.

**평가 행은 모든 모델이 같다.** 어느 한 모델이라도 쓸 수 없는 행은 전부에서 뺀다.
행 기준은 `results.json` 에 적고, 결합할 때 두 예측이 **같은 행을 가리키는지 단정**한다
(길이만 맞추면 안 된다 — 길이가 같은 다른 구간일 수 있다).

> **학습 범위는 모델마다 다르다. 그건 의도다.**
> 트리는 분할 이전의 모든 행으로 학습하고, 순환신경망은 **직전 3개월**만 쓴다
> (`config.NET["train_months"]`). 전진검증에서 그 편이 나았기 때문이다.
> 또 순환신경망은 걸러진 프레임에서 창을 다시 만들어 **앞 95행을 더 쓰지 못한다.**
> 그 95행은 2021-01-01 23:45 ~ 01-02 23:15 이고 **어느 평가 구간에도 들어가지 않는다**
> (실측 0행). 그래서 비교에는 영향이 없다.

## 핵심 — 날짜를 코드에 박지 않는다

2022년 자료를 받아 채점한다고 해도 돌아가야 한다. 그래서 `2021-07-13` 같은 날짜를
코드에 적지 않고, **자료를 보고 정하는 규칙**으로 썼다.

| 자료의 문제 | 규칙 |
|---|---|
| `시간` 열에 시가 아닌 값(70~188)이 들어 있다 | 0~23 정수·날짜 안 중복 없음을 검사. 깨졌고 그 날이 24행이면 **행 순서로 복구**(정상일 일치율이 임계값을 넘을 때), 아니면 그 날을 버린다 |
| 하루에 행이 모자라다 | `시간` 열이 정상이면 **그대로 쓴다.** 빠진 자리는 시각축 공백으로 남고 구간 분할이 막는다 |
| 날짜가 통째로 빠져 있다 | 구간을 나눠 모든 `shift`·`rolling` 이 공백을 넘지 못하게 한다 |
| 타깃에서 파생된 열이 섞여 있다 | 전력 열의 산술조합과 반올림 오차 안에서 일치하는 열을 찾아 뺀다 |
| 달력을 다시 적은 열이 있다 | 달력 키 그룹 안에서 값이 사실상 하나인 열을 찾아 뺀다 |
| 결측이 있다 | **엄격히 앞선 관측만** 보는 누적 중앙값으로 채운다 |
| 공휴일·휴무를 알 수 없다 | `calendar_YYYY.json` 으로 **받는다**. 안 주면 주말만 쓰고 그 사실을 기록하며, 자료에서 인과적으로 뽑은 `days_since_active` 가 장기 휴무를 대신한다 |

규칙이 무엇을 어떻게 판정했는지는 **`processed_manifest.json`** 에 전부 남는다.
다른 해 자료를 넣었을 때 무슨 일이 있었는지는 그 파일로 읽는다.

### 2021 자료에서 규칙이 실제로 잡아낸 것

```
시 열이 깨진 날 2일      07-13 · 07-15 → 정상일 255일에서 '행 순서 == 시간' 일치율 1.0000
                        이므로 행 순서로 복구 (버리지 않는다)
타깃 파생 2개            평균   = 네 전력열 평균을 정수로 반올림 (최대차 0.500)
                        공장인원 = 생산량 ÷ Σ전력 — 6,151행 전부 정확히 일치. **누수다**
                        → 항등식의 양쪽 중 `생산량` 은 보호 입력이라 남기고 `공장인원` 만 뺀다
달력 재표기 3개          전기요금(계절) = 월 · 인건비 = 시간 · day/d/m = 날짜
결측 4칸                풍속 3 · 강수량 1 → 엄격히 과거만 보는 누적 중앙값
```

### 다른 해에서도 돌아가는지 시험했다

`make_test_year.py` 가 2021 자료를 2022 로 옮기고 **문제의 위치와 종류를 바꿔** 심는다.
깨진 날을 03-07 로 옮기고, 한 주를 지우고, 하루를 21행으로 만들고, 결측을 기온·습도로
옮기고, 이름이 다른 파생 열(`설비효율`)과 달력 열(`요율구간`)을 더하고, `공장인원` 을 뺀다.

```bash
python make_test_year.py --raw <2021원자료> --out test_year_2022.csv
python preprocessing.py --raw test_year_2022.csv --out processed_2022.csv
```

규칙이 전부 잡았다 — 깨진 날 3일 복구, 21행짜리 하루는 **살려서** 공백으로 처리,
`설비효율`·`요율구간` 제외, 기온·습도 결측 대치, 공휴일 자료가 없다는 사실 기록.

## 실행

```bash
# ① 전처리 — 인수 없이 돌아간다 (Dataset/raw → Dataset/preprocessed)
python preprocessing.py

#    다른 해 자료
python preprocessing.py --raw <2022원자료.csv> --out <나갈 경로.csv>

#    분할 날짜는 calendar_2021.json 의 split_date 에서 읽는다.
#    달력을 안 주면 시간 순서 뒤 30% 로 자동 분할하고 그 사실을 manifest 에 적는다

# ② 모델링 — 전부 비교
python modeling.py

#    일부만 (트리만 돌리면 2분, 순환 계열까지면 2시간)
python modeling.py --models baseline,et,gru,ensemble

# ③ 검사
python verify_pipeline.py
```

`modeling.py` 는 **자기를 하위 프로세스로 두 번 호출한다**(`--only nets`, `--only trees`).
macOS 에서 sklearn(joblib 포크·OpenMP)과 torch 를 한 프로세스에서 쓰면 libomp 가 두 번
적재되어 교착하기 때문이다. CPU 0% 로 멈추고 죽는다. **환경변수로는 막히지 않는다.**
`--only` 는 내부용이니 직접 쓸 때는 빼고 부르면 된다.

## 비교하는 것

| 계열 | 모델 | 입력 |
|---|---|---|
| 기준선 | 직전값 유지 · 시각×요일 중앙값 | 학습하지 않는다 |
| 트리 | RandomForest · ExtraTrees · HistGradientBoosting | 표 형태 25변수 |
| 순환 | GRU · LSTM | 전력 계열 창 96칸 + 달력 6개 · **시드 3개 예측 평균** |
| 결합 | ExtraTrees + GRU | 고정 반반 |

세 트리 계열은 **같은 초모수**를 쓴다(공정 비교). 순환 계열도 같은 설정을 쓴다.

## 지키는 규약

- **선정은 전진검증 평균 MSE 로만 한다.** 시험 구간은 선정에 쓰지 않는다
- 전진검증 구간도 날짜를 박지 않는다 — 학습 구간의 마지막 달 시작일 네 개를 자료에서 뽑는다
- 순환신경망은 **시드 3개 예측을 평균**해 보고한다. 시험 성적으로 시드를 고르지 않는다
- 결합 가중치를 고르지 않는다 — 구간마다 최적이 반대 방향이라 고정 반반으로 둔다
- 시간 단위로 누적되는 열(`생산량`)은 반드시 지연시켜 쓴다. 그 시간이 끝나야 확정된다
- 결측 대치는 **자기 자신도 미래도 보지 않는다**(`expanding().median().shift(1)`)

## 한계

- 전진검증 4구간뿐이다. 0.5 이내 차이는 구별되지 않는다고 보는 편이 안전하다
- 시험 구간은 이 자료로 작업하는 동안 여러 번 관찰했다. 깨끗한 보류 자료가 아니다
- 자료가 1~9월 9개월뿐이라 **겨울을 검증하지 못했다**
- 파생·누수 열 탐지는 **산술조합**만 본다. 비선형 관계로 숨은 파생 열은 못 잡는다
- `시간` 열 복구는 '행 순서가 시각 순서' 라는 가정에 기댄다. 그 가정을 정상일에서
  측정해 임계값으로 걸러내지만, 측정할 정상일이 없으면 복구하지 않고 버린다

## 이후 붙을 것 — 인터페이스 계약

대시보드가 이 폴더를 가져다 쓴다. 설계가 어긋나지 않게 **무엇을 주고받는지만** 적어 둔다.
아래 둘은 **아직 만들지 않았다.**

```
원본 CSV ──npm run prepare:data──▶ pipeline/ ──▶ 입력 CSV + 학습된 모델
                                                      │
                                      backend/app.py ─┤ 예측·조회 API
                                                      │   └─ config.json (계절·시간대별 요금)
                                       optimization/ ─┘ 생산 목표·인원·비용
                                               src/     관제·자원 최적화 화면
```

**이 폴더가 지키는 쪽**

| 약속 | 지금 상태 |
|---|---|
| 인수 없이 CLI 로 돌아간다 (`npm run prepare:data` 에서 호출 가능) | ✓ `python preprocessing.py` |
| 출력 파일 이름을 바깥에서 정한다 | ✓ `--out final_input_data.csv` |
| 학습된 모델을 파일로 남긴다 | ✓ `model_<모델>.joblib` · `model_<모델>.pt` |
| 전처리 규칙이 **새 자료에도** 적용된다 | ✓ 날짜를 코드에 박지 않는다 |
| 모든 판정을 기록으로 남긴다 | ✓ `*_manifest.json` |

**아직 없는 것 — 붙일 때 필요하다**

- **`predict.py`** — 최근 원자료 몇 행을 받아 다음 15분을 내는 추론 진입점.
  지금은 `modeling.py` 가 학습·평가만 한다. 대시보드의 `backend/app.py` 는 이게 필요하다.
  전처리를 **같은 코드로** 거쳐야 학습 때와 입력이 같아진다 — 이 폴더를 그대로 불러 쓰면 된다
- **요금 계산** — `config.json` 의 계절·시간대별 요율은 이 폴더의 일이 아니다.
  전력 예측값만 내보내고 요금 환산은 `optimization/` 쪽에서 한다

**주의 — 순환신경망은 `.pt` 만으로 재현되지 않는다.** 보고 예측은 시드 3개 평균인데
저장 파일은 첫 시드 하나이고 표준화 통계를 담지 않는다. 대시보드가 순환 계열을 쓰려면
시드별 가중치와 표준화 통계를 함께 저장하도록 `modeling.py` 를 고쳐야 한다.
트리 계열(`joblib`)은 파일만으로 그대로 재현된다.


## 지금 결과

공통 24,576행 · 시험 4,991행 · 전진검증 4구간.

| 모델 | 전진검증 | ± | 시험 |
|---|---:|---:|---:|
| **ExtraTrees + GRU 앙상블** | **47.43** | 30.47 | **45.54** |
| ExtraTrees | 49.32 | 34.96 | 54.95 |
| HistGradientBoosting | 57.61 | 35.26 | 60.01 |
| GRU | 60.66 | 28.05 | 49.92 |
| LSTM | 63.16 | 33.99 | 57.66 |
| RandomForest | 91.68 | 61.09 | 120.10 |
| 직전값 유지 | 205.15 | 10.30 | 180.33 |
| 시각×요일 중앙값 | 1339.49 | 971.61 | 1540.36 |

**앙상블이 두 기준 모두 1위다.** 그러나 과하게 읽으면 안 된다 — 구간별 이득이
`+5.65 · −1.36 · −4.05 · +7.31` 로 **평균 +1.89 인데 표준편차가 4.73** 이다.
네 구간으로는 이득 자체가 확실하다고 말할 수 없다. 시험 구간 이득(+9.42)은 크지만
그 구간은 선정에 쓸 수 없다.

**GRU 와 LSTM 은 구별되지 않는다** — 구간별 차이가 `+2.14 · +0.45 · −4.76 · +12.17`
로 방향이 뒤집히고, 평균 +2.50 에 표준편차 6.13 이다.

**RandomForest 만 뚜렷이 밀린다**(91.68). 6/01 구간에서만 10.12 로 좋고 나머지에서
무너진다 — 전환대에서 평균 쪽으로 끌려가기 때문으로 보인다.

### 학습 예산이 모자란 구간이 있다

에폭 상한 200 에 닿은 경우:

```
GRU   20210401  [200, 200, 200]
LSTM  20210401  [200, 200, 200]
LSTM  20210601  [186, 145, 200]
LSTM  20210701  [130, 106, 200]
```

4월은 격주로 조업이 뒤집히는 구간이라 수렴이 안 된다. **상한을 올리면 어떻게 되는지는
재지 않았다.** LSTM 이 GRU 보다 자주 닿으므로 LSTM 쪽이 더 불리하게 측정됐을 수 있다.

### 저장하지 않는 모델

`model_et.joblib`(43MB)·`model_rf.joblib`(34MB)는 **2분이면 다시 학습되므로** 담지 않는다.

    python modeling.py --models et,rf,hgb

반대로 `model_gru.pt`·`model_lstm.pt` 는 작고(1MB) 다시 만들려면 두 시간이라 담는다.
