# 전력 관제 대시보드

React + TypeScript 화면과 FastAPI 모델 서버로 구성된 로컬 대시보드입니다. 토스 스타일의 밝은 화면, 파란 액션, 넉넉한 간격으로 설계했습니다.

## 실행

이 폴더에서 다음 명령을 실행합니다. 기존 프로젝트의 Python 3.13 / scikit-learn 1.7.1 환경에서 검증했습니다.

```sh
npm ci
python3 -m pip install -r backend/requirements.txt
npm run dev
```

주소: http://127.0.0.1:8065

`npm run dev`는 TypeScript 확인과 번들을 생성한 뒤 Python 서버를 시작합니다. 프론트엔드 자동 새로고침은 없으며 수정 후 `npm run build`하고 브라우저를 새로고침합니다. 이미 빌드된 화면은 `npm start`로 실행할 수 있습니다.

## 구현 범위

### 전력 관제

- 6단계 `final_model.joblib`의 실제 예측을 사용합니다. 임의 생성된 전력 수치가 아닙니다.
- `final_input_data.csv` 중 `split=test`인 7,294개 시점을 날짜별로 재생합니다.
- 현재값은 `forecast_time`의 `현재전력`, 예측값은 `target_time`의 다음 15분 전력입니다.
- 차트에는 재생 시점까지의 실제 관측만 표시합니다. 이전 예측은 대상 시간에 맞춰 정렬하고, 마지막 하나의 예측 점만 현재 시간 이후에 표시합니다. 30분·60분 다중 예측을 제공하지 않습니다.
- 삭제된 날짜/데이터 없는 날은 선택 목록에 표시하지 않습니다. 차트도 15분보다 큰 공백을 연결하지 않습니다.
- 날짜 변경, 이전/다음 이동, 슬라이더, 재생/정지, 1·2·4배속이 동작합니다.
- 운영 알림 기준은 AI 참고 추천을 기본으로 적용하고, 사용자가 직접 설정 모드로 바꿀 수 있습니다. 예측이 기준 이상이면 화면 경고와 토스트를 표시합니다. 브라우저 외부 알림이나 이메일·문자 발송은 없습니다.
- 최근 20개 기준 초과 예측과 확인 상태를 표시합니다. 확인 상태는 세션 내에서만 유지하며 기준은 localStorage에 저장합니다.
- CSV 내보내기에는 현재 시점까지 실제값과 마지막 단일 예측을 포함합니다.
- 모델 정보에는 실제 입력 목록, 모델 종류, 파일 SHA-256 앞 10자리, 재생 데이터 전체의 MSE와 MAE가 표시됩니다.

### 자원 최적화 탭

- 직전 45분에 생성한 정시 전력 예측과 해당 시간의 실제 생산 목표를 사용해 다음 1시간의 인원을 추천합니다.
- 같은 시간·평일/휴일 조건의 과거 기록 중 생산 목표 이상을 달성한 최소 정수 인원을 선택합니다. 적합한 기록이 없으면 추천 불가로 표시합니다.
- 생산 이익은 생산 목표 × 개당 이익이며, 인건비는 추천 인원 × 시급입니다. 22:00~06:00에는 시급 1.5배를 적용합니다.
- 전력량 요금은 정시 예측 전력이 1시간 유지된다는 가정에 따라 계산합니다. 2021년 계절·부하 시간과 토요일·일요일·공휴일 구분을 적용합니다.
- 기본 요금은 입력한 작년 피크 전력 × 기본 요금 단가를 월 일수와 24시간으로 나눠 배분합니다.
- 생산 이익·인건비·작년 피크 전력은 ‘기본값’ 체크 시 브라우저에 저장합니다. 전력 요금표는 적용 시 저장합니다.
- 시간당 영업 이익 = 생산 이익 − 인건비 − 전력량 요금 − 기본 요금 배분입니다. 세금 등 청구서 전체 항목을 재현하지는 않습니다.
- 자세한 시간대와 가정은 [optimization/README.md](optimization/README.md)를 참고하세요.

## 모델 교체

기본 모델은 `models/final_model.joblib`, 데이터는 `data/preprocessed/final_input_data.csv`에서 읽습니다. 대시보드 폴더 밖의 파일은 필요하지 않습니다. 교체 파일을 준비한 뒤 환경변수로 경로를 지정하고 서버를 재시작합니다.

```sh
MODEL_PATH='/absolute/path/new_model.joblib' \
DATA_PATH='/absolute/path/new_input_data.csv' \
npm start
```

모델 bundle 형식:

```python
{'estimator': sklearn_model_or_pipeline, 'features': ['입력열1', '입력열2', ...]}
```

`estimator.predict(DataFrame[features])`가 각 행에 유한한 스칼라 값을 반환해야 합니다. 데이터에는 features 전부와 `forecast_time,target_time,split,현재전력,전력`이 필요하고, 생산 환경 표시를 위해 `생산량,기온,풍속,습도,주중여부,주중공휴일여부`도 필요합니다. 생산량 가정 비교를 유지하려면 `생산량`이 모델 입력에 있어야 합니다. 예측 대상은 다음 15분 전력으로 맞춰야 합니다. 다른 모델 입출력은 backend에서 어댑터를 추가합니다.

신뢰할 수 있는 로컬 joblib만 사용합니다. joblib은 Python 객체를 복원하므로 외부 사용자의 업로드 파일을 직접 로드하는 기능은 제공하지 않습니다.

시작 시 모델을 한 번 로드하고 시험 데이터의 예측을 계산하여 메모리에 보관합니다. 비용 비교는 각 요청마다 실제 모델 추론을 수행합니다. 정적 화면과 API는 같은 서버에서 제공하므로 별도 CORS 설정이 필요하지 않습니다. 현재 서버는 127.0.0.1에만 연결됩니다.

## 알림 기준 추천과 연간 최대 피크

- 올해는 재생 날짜의 연도(현재 데이터는 2021년)를 뜻합니다. 연간 최대 피크는 전체 입력 CSV의 해당 연도 관측 중 `forecast_time <= 재생 시점`인 값에서 계산합니다. 학습 구간의 실제 관측도 포함하며 제공 파일의 시작일 이후 데이터만 포함합니다.
- 추천 기준 = 올해 관측 최대 피크 − 모델 과소예측 여유 (최소 1, 소수점 한 자리). 여유는 해당 연도 시험 예측 중 정답 시간이 현재 이전 또는 같은 경우의 `max(0, 실제−예측)` 90백분위입니다. 최소 30개의 확정된 예측이 필요합니다.
- 확정된 예측이 30개 미만이면 모델 bundle의 학습 교차검증 RMSE를 사용합니다. 교체 모델에 CV_MSE가 없으면 연간 최대의 5%를 초기 참고 가정으로 사용합니다.
- 이 방법은 기존 모델의 오차를 사용한 설명 가능한 휴리스틱이며 새로 학습한 최적 임계값 모델이 아닙니다. 90백분위가 미래 90% 보장을 뜻하지 않으며 실제 요금적용전력과도 별개입니다.
- 추천값은 재생 시점에 따라 갱신됩니다. 화면의 과거 알림 목록도 현재 선택된 기준으로 재평가하는 형태이며 불변 이벤트 로그가 아닙니다.
- 직접 설정은 `kamp-manual-threshold-v2`에 저장됩니다. 추천 모드로 복원하면 수동값을 지웁니다. 기존 180 고정 설정은 새 기본값으로 이관하지 않습니다.
- `backend.verify`에서는 미래 관측과 미래 정답을 임의로 크게 바꾸어도 현재 추천값과 연간 최대 피크가 변하지 않는 것을 검증합니다.

## 폴더 하나로 실행하기

이 폴더 전체를 다른 위치로 복사해도 동일하게 실행됩니다. Node.js와 Python 및 의존성은 설치되어 있어야 합니다. 데이터와 모델 파일을 찾는 기준은 현재 터미널 위치가 아니라 코드 파일의 위치입니다. 실행 명령은 이 폴더에서 수행합니다.

```text
Dashboard/

│   ├── raw/okm_augumented_2021.csv
│   └── preprocessed/final_input_data.csv
├── models/
│   ├── final_model.joblib
│   └── selection.json
├── pipeline/
│   ├── rebuild_data.py  # 원본 → 최종 입력 CSV
│   └── features.py      # 최종 입력에 필요한 변수 생성
├── backend/
├── optimization/
├── src/
├── package.json
└── package-lock.json
```

### 원본부터 전처리 재현

```sh
npm run prepare:data
npm run verify:model
```

파이프라인은 2021년 제공 원본에서 모델 입력을 생성합니다. 중간 단계는 메모리에서 처리하며 중간 CSV를 저장하지 않습니다. 기본 출력은 서버가 사용하는 `data/preprocessed/final_input_data.csv`입니다. 기존 최종 파일이 있으면 열·행·값 일치를 검증한 뒤 교체하며, 검증 실패 시 기존 파일을 유지합니다. 모델은 변경하지 않습니다.

다른 위치에 결과를 저장하려면:

```sh
python3 pipeline/rebuild_data.py --output /tmp/final_input_data.csv
```

처리 순서:

1. 원본의 15·30·45·60분 값을 행 순서대로 펼치고 다음 전력 정답을 shift(-1)합니다. 마지막 행의 현재 전력은 유지하고 정답은 결측으로 둡니다.
2. 7월 13일·15일의 48시간 행(15분 기준 192행)을 제거합니다.
3. 풍속 6월 1일 01·02시를 0.65, 7월 4일 20시를 1.85로 채웁니다. 강수량 1월 24일 00시는 6.3으로 채웁니다. 공장인원 결측은 보존합니다.
4. 2021년 주중·주중 공휴일 플래그를 넣고 날짜·평균을 제거합니다.
5. 끊긴 시간 구간을 넘지 않는 과거 전력·변화량·이동 평균/최대 피처를 생성합니다.
6. 원본에서 시간 주기·요일·월·분·이전 1시간 표준편차를 재구성하여 최종 선정 입력과 결합합니다. 이 단계는 기존 HS 파일을 읽지 않습니다.
7. 기존 모델과 동일한 시간 표기, 표본 제거, 학습/시험 및 경계 제외 구분을 적용해 24,190행·35개 입력 변수로 구성합니다.

`pipeline/features.py`는 원본에서 최종 입력을 만드는 공통 함수입니다. 그 안의 HS 컨텍스트 재구성은 앞선 누적 중앙값 처리 방식도 포함하지만, 현재 선정된 HS 변수에는 날씨·생산 컨텍스트가 포함되지 않습니다. 실제 모델에 입력되는 BG 풍속·강수량은 위의 협의한 대체값을 사용합니다. 이 파이프라인은 역사 데이터 재현용이며 새 연도 달력이나 새로운 결측·센서 포맷을 자동 처리하는 온라인 파이프라인은 아닙니다.

`bundle_manifest.json`에는 포함된 원본·전처리·모델 파일의 상대 경로와 SHA-256을 기록했습니다.

## 정시부터 1시간 인력 추천

자원 최적화 탭은 관제와 날짜·현재 시각을 공유합니다. 직전 45분에 생성한 정시 전력 예측으로 해당 정시부터 1시간의 인력과 비용을 계산합니다. 예: 11:45→12:00 예측, raw 12시 생산량으로 12:00~13:00 인력 산정. 인원은 과거 실적의 최소 정수 인원이며 전력비에는 정시 예측 전력이 1시간 유지된다는 가정을 적용합니다. [optimization/README.md](optimization/README.md)에 상세 계산을 정리했습니다.

자원 최적화의 생산 이익 초기값은 150원/개(인건비·전력비 차감 전)입니다. 하단 3계절×3부하 요금표를 편집해 적용하면 시간대별 단가가 자동 선택됩니다. 체크한 입력과 표는 브라우저 v2 기본값으로 저장되며 이전 판매단가/고정단가 v1 설정은 사용하지 않습니다.

### 한전 시간대와 기본 요금 편집 (2026-10-01)

요금표에서 기본 요금(원/kW)도 입력합니다. 상단 단가는 읽기 전용이며 최적화 대상 시간의 계절·부하를 자동 선택합니다. 2021년 기준 부하 시간을 자동 계산에 사용하며, 요청에 따라 화면의 시간·단위·출처 안내는 제거했습니다. 요금표 기본값 저장은 기본 요금과 9개 계절·부하 단가를 함께 저장합니다. 자세한 시간과 근거는 optimization/README.md를 참고하세요.
