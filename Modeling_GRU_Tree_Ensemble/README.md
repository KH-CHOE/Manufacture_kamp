# 트리 + 순환신경망 앙상블 — 다음 15분 전력 예측

`Modeling/`(ExtraTrees)과 `Modeling_RNN/`(GRU)을 **한쪽만 고르지 않고 평균낸** 판입니다.
같은 행·같은 분할에서 **전진검증과 시험 구간 양쪽 모두 1위**였습니다.

## 이 폴더가 낸 수치

**창 유효 23,904행 · 시험 7,104행** (`reproduction_metadata.json`)

| | 트리 | GRU | **앙상블** | 이득 |
|---|---:|---:|---:|---:|
| 전진검증 4구간 평균 | 39.017 | 49.301 | **37.495** | +1.52 |
| 시험 구간 | 60.718 | 56.928 | **51.568** | +9.149 |

시험 구간에서 단독 최고(56.928) 대비 **9.4% 감소**입니다.

> **행 기준을 먼저 밝힙니다.** 아래 "왜 섞는가" 절의 순위표(38.26 등)는 선정 실험의
> **23,425행** 기준이고, 위 표는 이 패키지의 **23,904행** 기준입니다.
> 같은 모형이라도 행 기준이 다르면 값이 달라집니다 — **두 표를 나란히 비교하지 마세요.**
> 순위표는 후보들 사이의 상대 순서를 보는 용도입니다.

> **전진검증 4구간 중 둘에서는 앙상블이 손해입니다.**
> 0401 39.017 → 55.26 · 0701 60.03 → 55.68 로 크게 벌지만,
> 0501 27.88 → 28.61 · 0601 8.41 → 10.44 로 잃습니다. **평균 이득이지 항상 이득이 아닙니다.**
> 버는 곳은 트리가 어려워하는 구간이고 잃는 곳은 트리가 이미 잘 맞히는 구간입니다.

## 왜 섞는가

두 모형은 **서로 다른 조건에서 무너집니다.**

| 모형 | 접근 | 약한 곳 |
|---|---|---|
| ExtraTrees | 달력으로 **분기**해 여러 체제를 따로 담는다 | — |
| GRU | 과거 계열을 **순서대로** 먹으며 흐름을 따라간다 | 격주로 뒤집히는 전환기(4월)에서 크게 무너진다 |

두 예측의 상관은 **0.996**으로 값이 거의 같은데도 평균내면 크게 줄어듭니다.
**틀리는 방향이 다르기** 때문입니다. 같은 계열끼리 섞으면(ExtraTrees + 부스팅) 거의 안 줄고,
다른 계열을 섞으면 큽니다.

## 핵심 파일

- `앙상블_보고서.html`: 전체 과정과 수치를 담은 독립 HTML 보고서.
- `reproduction_metadata.json`: 이 폴더가 낸 모든 수치의 출처. 보고서는 여기서 읽습니다.
- `reproduced_folds.csv` · `reproduced_metrics.csv` · `reproduced_test_predictions.csv`
- `final_tree.joblib` · `final_gru.pt`: 시험 구간 학습 모델(순환신경망은 첫 시드).
- `ensemble_input_data.csv`: 트리 25변수 + 전력 계열 + 순환신경망 달력 6종을 담은 CSV.
  `split`은 train/test/boundary_excluded — **`Modeling/final_input_data.csv`와 같은 분할**입니다.
- `selection.json`: 전진검증으로 확정한 구성, 선정 규칙, 결합 규칙.
- `train_gru_part.py`: **순환신경망만** 학습(torch 전용 프로세스). 시드 3회 × 5분할.
- `train_ensemble.py`: **트리만** 학습하고 위 결과를 읽어 결합(sklearn 전용 프로세스).
- `prepare_ensemble_input.py`: 원본 CSV에서 입력 재생성. `--verify`로 `Modeling/`과 값 대조,
  `--align`으로 그 행·분할에 맞춤.
- `build_report.py`: `reproduction_metadata.json`과 `evidence/`에서 보고서 생성. 재학습 없음.
- `evidence/`: 변수 선정·앙상블·파생변수·기온 실험 기록 10건.
- `requirements.txt`: 검증에 사용한 패키지 버전.

## 실행

```bash
python prepare_ensemble_input.py --raw <okm_augumented_2021.csv> \
    --align ../Modeling/final_input_data.csv     # ① 입력 생성 (정병근 행·분할에 맞춤)
python train_gru_part.py                         # ② 순환신경망 (torch 전용, 50~80분)
python train_ensemble.py                         # ③ 트리 + 결합 (sklearn 전용, 1분)
python build_report.py                           # ④ 보고서 (재학습 없음)
```

**②와 ③의 순서를 바꾸거나 합치지 마세요.** ②가 `_gru_predictions.npz` 를 만들고
③이 그것을 읽습니다. 이유는 아래에 있습니다.

`--align`을 빼면 원본만으로 자립 실행됩니다(날짜 규칙 20210627~ 시험으로 같은 분할 재현).
`--verify`를 주면 `Modeling/`의 같은 이름 변수와 **전 행 값을 대조**합니다 —
실험에서 그 CSV를 썼으므로 이 파일이 그것을 재현하는지 확인할 수 있습니다(현재 전부 일치).

> **왜 두 프로세스로 나눴나 (중요).**
> macOS에서 sklearn(joblib 포크·OpenMP)을 먼저 돌린 뒤 **같은 프로세스에서 torch Adam이
> 도는 순간 libomp가 두 번 적재되어 교착합니다.** CPU 0%로 멈추고 죽습니다.
> `faulthandler` 덤프로 `torch/optim/adam.py` 안에서 멈추는 것을 확인했습니다.
>
> **환경변수(`OMP_NUM_THREADS`·`KMP_DUPLICATE_LIB_OK`)로는 막히지 않습니다.** 실제로
> 시도했다가 세 번 실패했습니다. 이미 적재된 libomp에는 영향을 주지 못합니다.
>
> 그래서 `train_gru_part.py` 는 **torch만**, `train_ensemble.py` 는 **sklearn만**
> import 합니다. 두 파일을 합치거나 한쪽에 다른 라이브러리를 들이지 마세요.
> `Modeling_RNN/` 도 같은 이유로 분리돼 있습니다.
>
> 두 프로세스가 **같은 창 규칙**(불연속 창 제외)을 써야 예측 길이가 맞습니다.
> `train_ensemble.py` 가 `assert` 로 검사합니다.

## 트리 변수 25개 — 왜 이것인가

모든 판정은 **전진검증 4구간 평균 MSE**로 했습니다. 시험 구간은 선정에 쓰지 않았습니다.

### 가장 큰 발견 — 트리에는 시각 **원값**이 필요합니다

트리는 `변수 ≤ 임계값`으로만 자릅니다. `시간 ≥ 7`(오전 시동)을 **한 번의 분기**로 만들려면
원값이 있어야 합니다. 순환 인코딩(sin/cos)만 주면 두 변수를 여러 번 잘라야 그 경계가 생깁니다.

| 설정 | 변수 | 전진검증 |
|---|---|---|
| 우리 원래 변수 | 21 | 46.58 |
| **+ 시각 원값** | 24 | **41.75** |
| − sin/cos + 시각 원값 | 22 | 44.41 |
| + `시간`(hour)만 | 22 | 46.19 |
| − sin/cos (시각 정보 없음) | 19 | 54.05 |

**`시간`만으로는 부족하고 `15분위치`까지 있어야 하며, sin/cos도 같이 두는 편이 낫습니다.**
순환 인코딩은 신경망에는 맞지만 트리에는 불리합니다.

### 넣은 것과 뺀 것

| | 변수 | 근거 |
|---|---|---|
| 넣음 | 시각 원값 `시간`·`15분위치` | 46.58 → 41.75 |
| 넣음 | 최근 2·4시간 통계 7종 | 빼면 41.61 → 43.29 |
| 뺌 | 기상 4종 | 빼면 39.88 → 39.77 |
| 뺌 | 1주 전 `kw_lag672` | 넣으면 41.61 → 45.05 |

**중복 변수를 하나 찾아 뺐습니다.** `Modeling/`의 `HS_분`은 `15분위치`의 순서만 바꾼 것입니다
(교차표가 완전한 일대일). 빼도 39.66 → 39.74로 차이가 없어 25변수로 정리했습니다.
`Modeling/`에서도 빼도 됩니다.

**기상을 뺀 이유를 오해하지 마세요.** 기온이 전력에 영향을 주기는 합니다 — 비가동 기저부하가
−3.4℃에서 25.7 kW, 17.4℃에서 22.4 kW로 **U자**입니다(난방만 하고 냉방은 거의 안 합니다).
그런데 **모형 성능으로는 이어지지 않습니다.** 직전 전력이 이미 그 정보를 담고 있기 때문입니다.
기온을 `|기온 − 중앙값|`이나 난방도로 바꿔도 개선이 −0.13으로 사실상 없었습니다.

## 결합 — 가중치를 고르지 않습니다

**고정 0.5 : 0.5**입니다.

| 방식 | 가중치 | 결과 | 행 기준 |
|---|---|---|---|
| **고정 0.5 : 0.5 (채택)** | — | 시험·전진검증 어느 쪽도 선정에 쓰지 않는다 | — |
| 전진검증으로 역산한 최적 (진단) | 트리 0.70 | 36.51 (고정 반반 37.49, 차이 +0.99) | 23,904 |
| 정병근 시험 구간으로 역산한 최적 (진단) | 트리 0.43 | 51.90 (고정 반반 52.07, 차이 −0.17) | 7,104 |
| 시험 앞 20%로 학습해 뒤 80%에 적용 | 트리 0.75 | **같은 구간 고정반반보다 3.9 나쁨** | 7,104 |

**구간마다 최적이 반대 방향입니다.** 전진검증 쪽은 트리로, 시험 구간 쪽은 순환신경망(0.43)으로
기웁니다. 그리고 실제로 가중치를 학습시키면 오히려 나빠집니다. 작은 이득에 선정 편향을
사지 않습니다.

> **전진검증 최적값을 여기 적지 않는 이유.** 예전 README 에는 "트리 0.69 · 31.06
> (고정 반반 32.00)" 이 적혀 있었는데 **어떤 결과 파일에도 없는 수치였습니다**
> (코덱스 리뷰 R10). 지금은 `train_ensemble.py` 가 실제로 훑어서
> `reproduction_metadata.json` 에 남기고, README 는 그 파일을 가리킵니다.
> **그 값은 진단이며 가중치 선정에 쓰지 않았습니다** — 그 4구간으로 가중치를 고르면
> 같은 구간이 선정에 쓰인 것이 됩니다.

## 순환신경망은 시드 3개 예측을 평균냅니다

**시험 성적으로 시드를 고르지 않습니다.** 저장 모델은 첫 시드로 고정합니다.

탐색 중 한 설정이 시드 42에서 평가 54.99, 시드 7에서 135.30으로 **2.5배** 벌어진 적이
있습니다. 더 문제는 **시드 7의 전진검증이 세 시드 중 가장 좋았다**는 것입니다 —
전진검증이 그 취약점을 경고하지 못했습니다. 단일 시드 수치를 인용하지 마세요.

## 안 된 것 — 기록해 둡니다

분석에서 나온 사실마다 파생변수를 만들어 **23개를 6묶음**으로 시험했습니다.
**대부분 안 됐습니다.**

- **변수를 많이 더할수록 나빠집니다.** 전부 넣으면 +2.19
- 살아남은 것은 **B 전환감지**(`slope4`·`rng4`·`absd4`·`is_ramp`) 하나뿐이고
  −0.56으로 구별 기준(0.5) 경계입니다. 다만 부스팅에서도 −1.21로 유지되어
  트리 계열 일반 효과로 보입니다
- **순환신경망에는 파생변수가 전부 해로웠습니다.** 트리에서 유일하게 살았던 B가
  GRU에서는 가장 해롭습니다(+8.50). GRU는 계열을 그대로 받으므로 그 요약은 중복이고
  출력단 스칼라라 잡음만 늘립니다. **같은 파생변수가 모형 종류에 따라 정반대로 작용합니다**

**누수 검사가 하나를 잡았습니다.** `temp_range_day`(일교차)를
`groupby(날짜).transform('max') − min`으로 만들었는데, 이건 **아침 8시에 그날 최고기온을
아는 것**입니다. "지금까지의 누적 일교차"로 고친 뒤에야 통과했습니다.

## 행 기준 주의

이 저장소 안에 시험 행수가 여럿 있습니다.

| 폴더 | 시험 행수 | 왜 다른가 |
|---|---|---|
| `Modeling/` | 7,294 | 트리는 모든 행을 쓸 수 있다 |
| `Modeling_RNN/` | 7,104 | 창 96칸을 만들 수 없는 190행 제외 |
| 이 폴더 | 7,104 | 같은 이유 (창 유효 23,904행 중 시험분) |

제외되는 행은 **삭제된 2021-07-13·15 주변**이고, `Modeling/` 기준으로 그 190행은
**쉬운 구간**입니다(ExtraTrees MSE 16.05). 그래서 같은 행으로 맞추면 수치가 달라집니다.
**같은 기준끼리만 비교하세요.**
